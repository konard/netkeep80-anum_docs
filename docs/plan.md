# План стабилизации рабочей МТС

## Цель

Собрать текущую рабочую МТС так, чтобы система аксиом, формальная нотация, тест формул и структура документации проверяли друг друга.

## Критерий готовности

1. README является точкой входа в текущую МТС.
2. `docs/theory/Шаблон аксиом МТС.md` задаёт нормативный критерий готовности аксиомы.
3. `docs/theory/Система аксиом МТС.md` построена по этому шаблону.
4. Каждый символ, используемый в формулах ядра, имеет аксиому или явный служебный статус.
5. `tests/mtc_formulas.mtc` содержит только чистые формулы МТС и комментарии.
6. Регрессионные тесты запрещают служебный DSL в `.mtc`.
7. `{}` отделено от пустого множества, пустого результата поиска, несвязи и `0`.
8. `{s}` отделено от `{}`.
9. Последовательная запись форм читается как связь с явной группировкой операндов и левой сборкой по умолчанию.
10. `[]` остаются только в слое ачисел и сериализации.

## Рабочее ядро

```text
∞ : {} = {} ⟼ {}
∞ = ∞ ⟼ ∞

({}) = {}

{}{} : ({}) ⟼ {}
{}({}) : {} ⟼ ({})
{}{} : {} ⟼ {}
{}{} = {} ⟼ {}

{}{}{} : ({}{}) ⟼ {}
{}{}{} = (({}) ⟼ {}) ⟼ {}
{}{}{} = {} ⟼ {} ⟼ {}

{}({}{}) : {} ⟼ ({}{})

♂{} : ♂{} = ♂{} ⟼ {}
♂∞ = ♂∞ ⟼ ∞

{}♀ : {}♀ = {} ⟼ {}♀
∞♀ = ∞ ⟼ ∞♀

{[} : ∞♀
{]} : ♂∞

{[}{]} = {[} ⟼ {]}
{⟼} : {[}{]}
{⟼} = {[} ⟼ {]}
```

Метаязыковое ограничение: последовательная запись `{}{}{}` не читается как правая группировка `{}({}{})`. Это правило чтения записи, а не формула МТС.
