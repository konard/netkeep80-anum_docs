# Открытые вопросы новой аксиоматики МТС

Статус: рабочее.

## Назначение

Этот регистр собирает нерешённые вопросы текущей аксиоматики, чтобы актуальные документы могли фиксировать рабочую рамку без притворной завершённости. Если вопрос находится здесь, его нельзя подавать как стабилизированную часть спецификации.

## Уже введённый корневой слой

Следующие темы зафиксированы как рабочие формулы, а не как вопросы регистра:

- смысл связи;
- конкретная связь;
- инверсия формы связи;
- смысл равенства;
- смысл неравенства;
- абиты квадратной нотации;
- `∞ не является абитом`;
- `¬[=] не означает !=`.

Канонический блок:

```text
∞♀ : [⟼]♀
♂∞ : ♂[⟼]

(⟼) : [] ⟼ []
[⟼] : ∞♀ ⟼ ♂∞

¬[] : ♂[] ⟼ []♀
¬[⟼] : ♂[⟼] ⟼ [⟼]♀
¬[⟼] : ♂∞ ⟼ ∞♀

(=) : {[]♀ = []♀, ♂[] = ♂[]}
(!=) : ¬(=)
[] != [] : ¬([] = [])

↛ : ¬[⟼]

[ : ∞♀
] : ♂∞
1 : [⟼]
0 : [↛]
```

## Вопросы

1. Пустой результат поиска.

   Нужно определить, существует ли отдельный знак для отсутствия результата шаблонного поиска. `{}` уже занято поиском без фильтра и не может означать пустой результат.

2. Независимые шаблонные поиски вне последовательностной записи.

   Сейчас действует правило: внутри одного исполнения шаблона все одинаковые вхождения `{}` относятся к одной и той же связи-кандидату. В последовательности `{}{}...` каждое `{}` задаёт позицию. Нужно ввести нотацию для нескольких независимых кандидатов в других видах формул.

3. Статус `{` и `}`.

   Открыто, являются ли фигурные скобки внутренними знаками МТС или служебными знаками формальной нотации.

4. Точный смысл `:`.

   Рабочее чтение: `:` вводит знак для смысла, найденного по форме. Нужно решить, сводится ли этот механизм к отдельной аксиоме.

5. Позиционное чтение повторных `[]`.

   Нужно формализовать случаи, где повторные `[]` читаются как один образец, и случаи, где они читаются как разные позиции сравнения или последовательности.

6. Модель результата сравнения.

   Нужно определить тип результата `[] = []`, связь результата с `[] != []` и правила последующего применения `¬`.

7. Строгая семантика `↛`.

   Нужно определить, как несвязь соотносится с отсутствием связевой формы, пустым результатом поиска и сериализацией.

8. Связь `0` с сериализацией отсутствия.

   `0 : [↛]` фиксирует рабочий переход, но нужна строгая модель того, как `0` кодирует отсутствие связевой формы.

9. Связь шаблонного поиска с парсером.

   Нужно решить, какие проверки должен выполнять будущий parser/test-runner для `tests/mtc_formulas.mtc`, включая группировку, прямоассоциативность последовательностей и одиночные определения абитов `[`, `]`.

10. Асеть как результат десериализации ачисла.

    Нужно описать, как структура, восстановленная из ачисла, соотносится с асетью и со смысловыми шаблонами, не смешивая эти уровни.

11. Теория переменных и подстановки.

    Нужно ввести отдельную теорию метаязыковых имён, позиционных форм и подстановки, чтобы `A`, `B`, `X` оставались пояснениями, а не внутренними символами МТС.
