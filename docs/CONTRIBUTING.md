# Руководство по вкладу в проект

Спасибо за интерес к проекту протокола ачисел МТС! Этот документ описывает процесс внесения вклада.

## Быстрый старт

1. Форкните репозиторий
2. Создайте ветку для вашей функциональности (`git checkout -b feature/amazing-feature`)
3. Внесите изменения
4. Запустите локальные проверки (см. ниже)
5. Закоммитьте изменения (`git commit -m 'Добавить amazing feature'`)
6. Запушьте в ветку (`git push origin feature/amazing-feature`)
7. Откройте Pull Request

## Правила размещения файлов

### Запрещённые действия

- **НЕ создавайте файлы в корне проекта** — все файлы должны быть в соответствующих подкаталогах
- **НЕ используйте старую нотацию абитов** (♂, ♀, →, ,) — только корректная: `[`, `]`, `1`, `0`
- **НЕ трактуйте ∞ как абит** — это мета-конструкт, выражаемый как `[] = ∞`

### Правильное размещение файлов

| Тип файла | Каталог |
|-----------|---------|
| Тестовые файлы (`.anum`, `.mtc`) | `tests/` |
| Скрипты парсеров | `parsers/` |
| Документация | `docs/` |
| Примеры | `examples/` (если будет создан) |
| Инструменты | `tools/` (если будет создан) |
| Конвертеры | `converters/` |

## Локальные проверки перед коммитом

### Python

```bash
# Запустите все тесты
python3 -m pytest tests -v

# Или на Windows
py -m pytest tests -v

# Проверка с помощью ruff (если установлен)
ruff check parsers/ converters/ core/ tests/ --ignore E501,F401
```

`tests/issue42_mtc_formulas.mtc` — актуальная спецификационная fixture новой рамки. `tests/legacy_mtc_formulas.mtc` оставлен только для старого прувера формул.

### Проверка размера файлов

Файлы кода не должны превышать 1500 строк:

```bash
find . -name "*.py" -type f -exec wc -l {} \; | awk '$1 > 1500 {print "СЛИШКОМ БОЛЬШОЙ:", $2, "(" $1 " строк)"}'
```

## Нотация МТС

После issue #42 актуальная документация различает формальную нотацию смыслов и ачисла.

Короткое правило:

```text
{} — шаблонный поиск без фильтра в формальной нотации.
[] — абиты и слой сериализации ачисел.
∞ : {} = {} ⟼ {} — рабочая форма аксиомы акорня.
```

Не добавляйте новые тексты, где `{}` трактуется как пустое множество, а `[]` используются как формульная группировка или универсальное экранирование. Старые формулы А0-А16 можно обсуждать как исторический материал, но не как текущую финальную систему.

### ASCII совместимость

```
[   = [    (начало смысла — абит)
]   = ]    (конец смысла — абит)
1   = 1    (связь/единица смысла — абит)
0   = 0    (несвязь/нуль смысла — абит)
[]  = ∞    (акорень)
M   = ♂    (самозамкнутое начало)
F   = ♀    (самозамкнутый конец)
->  = ⟼    (направленная связь)
!-> = ↛    (отсутствие связи)
```

## Процесс Pull Request

### Заголовок PR

Используйте чёткий, описательный заголовок на русском языке:

- `Добавить поддержку X в парсере`
- `Исправить обработку ошибок в конвертере`
- `Обновить документацию по аксиомам`

### Описание PR

Используйте следующий шаблон:

```markdown
## Summary

[Краткое описание изменений]

Fixes #<номер issue>

### Что изменено

- Пункт 1
- Пункт 2
- Пункт 3

## Test plan

- [ ] Тесты проходят локально
- [ ] Новая функциональность протестирована
- [ ] Документация обновлена (если применимо)
- [ ] Все CI/CD проверки проходят

🤖 Generated with [Claude Code](https://claude.com/claude-code)
```

## Получение помощи

Если у вас есть вопросы:

1. Проверьте существующую документацию в `docs/`
2. Посмотрите FAQ в `faq/`
3. Создайте issue с вопросом
4. Обратитесь к чистовику МТС: `docs/theory/Метатеория связей.md`
