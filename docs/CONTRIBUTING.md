# Руководство по вкладу в проект

## Рабочая ветка

Изменения вносятся через pull request. Перед отправкой запускайте локальные проверки из README.

## Структура проекта

```text
ROOT/
├── README.md
├── LICENSE
├── core/
├── converters/
├── tests/
└── docs/
    ├── theory/
    └── specs/
```

В рабочем дереве хранится текущая МТС: спецификации, тесты и инструменты. Материалы, которые не входят в актуальную систему, не добавляются.

## Нотация МТС

```text
(...) — круглая формальная нотация
[...] — квадратная ачисловая нотация
{...} — пучковая нотация
```

```text
[] — минимальная завершённая форма одной связи
() — минимальная формальная форма смысла
{} — пустой пучок связей
0 — абит связи, несущей смысл несвязи
↛ — смысл несвязи
```

связь — единственная форма существования. существовать — значит быть связью. Смысл не существует отдельно от связи, а связь и есть смысл в своей различённой форме. Несвязь не существует в натуре; смысл несвязи выражается связью. Акорень несёт смысл смысла.

## Корневые формулы

`tests/mtc_formulas.mtc` содержит текущий словарь:

```text
∞ : [] = [] ⟼ []
[] = ∞
∞ = ∞ ⟼ ∞

() : ♀() ⟼ ()♂

([) : (♀∞)
(]) : (∞♂)

(⟼) : (♀∞ ⟼ ∞♂)
(↛) : (∞♂ ⟼ ♀∞)

[1] : (⟼)
[0] : (↛)

(=) : {[]♀ = []♀, ♂[] = ♂[]}
```

Равенство фиксирует совпадение форм связей и не требует бесконечного раскрытия рекурсивных связей.

## Проверки

```bash
python -m pytest tests -v --tb=short
ruff check converters/ core/ tests/ --ignore E501,F401
git diff --check
```

## Стиль

- Кодировка файлов: UTF-8.
- Python-код должен сохранять явные проверки ошибок пользовательского ввода.
- Документация должна описывать только текущую систему.
- Новая формула должна иметь тест или проверку документации, если она меняет нормативную поверхность.
