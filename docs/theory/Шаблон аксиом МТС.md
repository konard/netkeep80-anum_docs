# Шаблон аксиом МТС

## Принцип после issue #42

Аксиома МТС — это не описание частного объекта и не простая ссылка имени на готовую связь.

```text
аксиома = определение вида формы смысла через шаблон поиска
```

Каждая аксиома должна вводить один смысловой механизм и явно показывать, к какому слою нотации относится запись.

## Обязательный формат

### N. Название аксиомы

**Вводимый знак**

Какой знак вводится и в каком слое он находится.

**Уровень**

Один из уровней:

- смысл связи;
- шаблон поиска;
- формальная нотация;
- ачисло / сериализация;
- асеть / остенсивная модель;
- метаязыковое пояснение.

**Формула**

```text
знак : шаблон формы
```

**Шаблонное чтение**

Какой поиск задаёт формула. Нужно явно указать, что ищется, какая часть является кандидатом и какие ограничения накладываются.

**После исполнения шаблона**

Какая привычная или сокращённая запись допустима после нахождения смысла.

**Что различается**

Какой новый смысловой механизм вводит аксиома и чем он отличается от уже введённых механизмов.

**Запрещённые чтения**

Какие старые толкования больше нельзя использовать.

**Связи с другими аксиомами**

Какие определения нужны для чтения этой аксиомы и какие следствия она открывает.

**Открытые вопросы**

Что ещё не стабилизировано и не должно подаваться как доказанный факт.

## Минимальный пример

### Акорень

**Вводимый знак**

`∞`

**Уровень**

Смысл связи через шаблон поиска.

**Формула**

```text
∞ : {} = {} ⟼ {}
```

**Шаблонное чтение**

Найти смысл, для которого связь-кандидат тождественна связи этой же формы с самой собой.

**После исполнения шаблона**

```text
∞ : ∞ ⟼ ∞
```

**Запрещённые чтения**

- `{}` как пустое множество;
- `∞` как абит;
- `∞ : ∞ ⟼ ∞` как исходная тавтология без шаблонного поиска.
