# Система аксиом МТС

Статус: рабочее.

Документ фиксирует корневую систему формул, отражённую в `tests/mtc_formulas.mtc`.

## Система аксиом как корневая библиотека апрувера

Каждая аксиома имеет формулу формальной нотации МТС. Система формул аксиом решается одновременно. Система формул аксиом составляет корневую библиотеку апрувера.

Документация ниже поясняет формулы, но не заменяет их. Если у аксиомы нет формулы, она не входит в корневую библиотеку как аксиома.

## Служебная рамка

Перед чтением аксиом действуют три первичные скобочные нотации:

```text
(...) — явная формальная форма / группировка формы
[...] — нотация ачисла; форма одной связи
{...} — пучковая нотация; форма пучка / асети связей
```

`:` остаётся служебным введением различия через формулу. `=`, `!=`, `⟼`, `¬`, `↛` получают рабочие корневые формулы ниже, но их полная модель для будущего апрувера остаётся открытой.

## R1. Акорень через пустую форму одной связи

**Формула**

```text
∞ : [] = [] ⟼ []
[] = ∞
∞ = ∞ ⟼ ∞
```

**Какие различия вводит**

`∞` как полное самозамыкание и `[]` как пустую форму одной связи.

**Как читается**

Акорень вводится через интерпретацию пустой формы одной связи:

```text
[] — пустая форма одной связи
[] = ∞
```

После этой фиксации допустима развёртка:

```text
∞ = ∞ ⟼ ∞
```

**Что запрещает**

- `[]` не является универсальной переменной;
- `∞` не является абитом квадратной нотации;
- развёртка не заменяет формулу введения.

**Открытые вопросы**

Точная аксиоматизация `:` и `=`.

## R2. Круглая группировка формы

**Формула**

```text
([]) = []
([][]) = [][]
([] ⟼ []) = [] ⟼ []
```

**Какие различия вводит**

Круглые скобки как явную границу уже имеющейся формальной формы.

**Как читается**

Круглая группировка не меняет интерпретацию формы, но фиксирует её как один операнд там, где это нужно для приоритета.

**Что запрещает**

- круглые скобки не являются формой одной связи;
- пустое `()` не входит в корневую систему;
- группировка не задаёт новую связь сама по себе.

**Открытые вопросы**

Статус пустой круглой формы.

## R3. Последовательность двух форм

**Формула**

```text
[][] : [] ⟼ []
[][] = [] ⟼ []
```

**Какие различия вводит**

Последовательную запись двух форм как связь первой формы со второй формой.

**Как читается**

Две формы подряд дают форму связи:

```text
[][] = [] ⟼ []
```

**Что запрещает**

- последовательность не является строковым ачислом сама по себе;
- последовательность не отменяет квадратную нотацию формы одной связи.

**Открытые вопросы**

Как будущий апрувер различает позиции последовательности и повтор внутри шаблона.

## R4. Последовательность трёх форм

**Формула**

```text
[][][] : ([][]) ⟼ []
[][][] = ([] ⟼ []) ⟼ []
[][][] = [] ⟼ [] ⟼ []

[]([][]) : [] ⟼ ([][])
[][][] != []([][])
[][][] != [] ⟼ ([] ⟼ [])
```

**Какие различия вводит**

Левую сборку последовательности по умолчанию и явную правую группировку.

**Как читается**

Три формы подряд собираются слева:

```text
[][][] = ([] ⟼ []) ⟼ []
```

Правая группировка требует круглых скобок:

```text
[]([][]) : [] ⟼ ([][])
```

**Что запрещает**

- последовательность не является правоассоциативной по умолчанию;
- `[][][]` не тождественно `[]([][])`.

**Открытые вопросы**

Полная индукция последовательностей произвольной длины.

## R5. Самозамкнутое начало

**Формула**

```text
♂[] : ♂[] = ♂[] ⟼ []
♂∞ = ♂∞ ⟼ ∞
```

**Какие различия вводит**

`♂` как префиксный вид формы с самозамкнутым началом.

**Как читается**

`♂[]` задаёт форму, у которой начало удерживает эту же форму, а конец остаётся формой одной связи.

**Что запрещает**

- `♂` не является самостоятельной связью без операнда;
- эта формула не вводит абиты `[`, `]`, `1`, `0`; они вводятся в R15.

**Открытые вопросы**

Связь `♂` с будущей формализацией извлечения конца связи.

## R6. Самозамкнутый конец

**Формула**

```text
[]♀ : []♀ = [] ⟼ []♀
∞♀ = ∞ ⟼ ∞♀
```

**Какие различия вводит**

`♀` как постфиксный вид формы с самозамкнутым концом.

**Как читается**

`[]♀` задаёт форму, у которой конец удерживает эту же форму, а начало остаётся формой одной связи.

**Что запрещает**

- `♀` не является самостоятельной связью без операнда;
- эта формула не вводит абиты `[`, `]`, `1`, `0`; они вводятся в R15.

**Открытые вопросы**

Связь `♀` с будущей формализацией извлечения начала связи.

## R7. Фигурная пучковая нотация

**Формула**

```text
{} != []
{[]} != []
{[], []} = {[]}
{[], [][]} = {[][], []}
```

**Какие различия вводит**

Фигурный контейнер как форму пучка / асети связей.

**Как читается**

`{}` — пустой пучок связей. `{[]}` — пучок из одной формы одной связи. Пучок экстенсионален: порядок элементов не важен, а повтор элемента не создаёт новый элемент.

**Что запрещает**

- пустой пучок не является пустой формой одной связи;
- одноэлементный пучок не является своим элементом;
- операционное удаление не входит в корневую формулу.

**Открытые вопросы**

Мультпучки, операции над пучками и связь с асетью.

## R8. Пучковое раскрытие

**Формула**

```text
[]{[], [][]} = {[] ⟼ [], [] ⟼ [][]}
{[], [][]}[] = {[] ⟼ [], [][] ⟼ []}
{[], [][]}{[], [][]} = {[] ⟼ [], [] ⟼ [][], [][] ⟼ [], [][] ⟼ [][]}
```

**Какие различия вводит**

Правое, левое и двустороннее раскрытие пучковой формы.

**Как читается**

Правая форма строит пучок исходящих связей. Левая форма строит пучок входящих связей. Двусторонняя форма строит произведение связей между элементами левого и правого пучков.

**Что запрещает**

- пучковое раскрытие не является операционным действием;
- формулы раскрытия не вводят переменные или подстановку.

**Открытые вопросы**

Как выразить операции над всеми входящими или исходящими связями без дополнительной нотации.

## R9. Начало и конец акорня

**Формула**

```text
∞♀ : [⟼]♀
♂∞ : ♂[⟼]
```

**Какие различия вводит**

`∞♀` как начало акорня и `♂∞` как конец акорня.

**Как читается**

Начало акорня извлекается как начало конкретной связи `[⟼]`. Конец акорня извлекается как конец конкретной связи `[⟼]`.

**Что запрещает**

- начало и конец акорня не выводятся из внешнего placeholder;
- `∞` не становится абитом;
- `[⟼]` нельзя смешивать со смыслом связи `(⟼)`.

**Открытые вопросы**

Полная модель извлечения начала и конца для произвольных форм связи.

## R10. Смысл связи и конкретная связь

**Формула**

```text
(⟼) : [] ⟼ []
[⟼] : ∞♀ ⟼ ♂∞
```

**Какие различия вводит**

`(⟼)` как смысл связи и `[⟼]` как конкретную связь.

**Как читается**

`(⟼)` задаёт смысл связи как формы связи одной связи с другой связью. `[⟼]` задаёт конкретную связь как связь начала акорня с концом акорня.

**Что запрещает**

- нельзя отождествлять знак `⟼`, смысл `(⟼)` и конкретную связь `[⟼]`;
- нельзя вводить конкретную связь формулой через общую форму `[]♀` и `♂[]`;
- `[⟼]` не является смысловой ссылкой через фигурные скобки.

**Открытые вопросы**

Как будущий апрувер различает знак, смысл знака, конкретную связь знака и результат применения смысла.

## R11. Инверсия формы связи

**Формула**

```text
¬[] : ♂[] ⟼ []♀
¬[⟼] : ♂[⟼] ⟼ [⟼]♀
¬[⟼] : ♂∞ ⟼ ∞♀
```

**Какие различия вводит**

`¬` как инверсию формы связи и конкретной связи.

**Как читается**

Инверсия формы связи есть связь её конца с её началом. Поэтому конкретная связь `[⟼] : ∞♀ ⟼ ♂∞` имеет инверсию `¬[⟼] : ♂∞ ⟼ ∞♀`.

**Что запрещает**

- `¬` не является произвольным отрицанием без операнда;
- `¬` не должен неявно применяться к конкретной связи знака там, где требуется смысл знака;
- `0` не вводится прямым отождествлением с инверсией связи.

**Открытые вопросы**

Строгие границы применения `¬` к смыслу, результату применения смысла и конкретной связи.

## R12. Смысл равенства

**Формула**

```text
(=) : {[]♀ = []♀, ♂[] = ♂[]}
```

**Какие различия вводит**

`(=)` как смысл равенства.

**Как читается**

Смысл равенства определяется совпадением начал и совпадением концов сравниваемых форм связи.

```text
A = B
⇔
A♀ = B♀
и
♂A = ♂B
```

Повторные `[]` в этой формуле читаются позиционно, а не как тавтология одного и того же места.

**Что запрещает**

- равенство не вводится как абстрактная неразличимость без структуры начала и конца;
- повторные `[]` в формуле равенства нельзя читать только как один образец;
- `(=)` не является конкретной связью знака равенства.

**Открытые вопросы**

Полная модель результата сравнения и тип результата `[] = []`.

## R13. Неравенство как инверсия смысла равенства

**Формула**

```text
(!=) : ¬(=)
[] != [] : ¬([] = [])
```

**Какие различия вводит**

`(!=)` как смысл неравенства и `!=` как запись результата конкретного сравнения.

**Как читается**

Неравенство является инверсией смысла равенства. Конкретная запись `[] != []` читается как инверсия результата сравнения `[] = []`.

**Что запрещает**

- `¬[=] не означает !=`;
- инверсия конкретной связи знака равенства не является смыслом неравенства;
- `[=]`, если будет введена, не должна смешиваться с `(=)`.

**Открытые вопросы**

Как будущий апрувер различает смысл равенства, конкретную связь знака равенства и результат конкретного сравнения.

## R14. Несвязь

**Формула**

```text
↛ : ¬[⟼]
```

**Какие различия вводит**

`↛` как несвязь, введённую через инверсию конкретной связи.

**Как читается**

`↛` является промежуточным смыслом для абита `0`. Он сохраняет различие между инверсией конкретной связи и практической записью отсутствия связи.

**Что запрещает**

- `↛` не отождествляется автоматически с пустым пучком;
- `↛` не отождествляется автоматически с абитом `0` без формулы `0 : [↛]`;
- `0` не является прямой инверсией `1`.

**Открытые вопросы**

Строгая семантика `↛`.

## R15. Абиты квадратной нотации

**Формула**

```text
[ : ∞♀
] : ♂∞
1 : [⟼]
0 : [↛]
```

**Какие различия вводит**

`[`, `]`, `1`, `0` как абиты квадратной нотации.

**Как читается**

`[` — абит начала. `]` — абит конца. `1` — абит конкретной связи. `0` — абит несвязи / отсутствия связевой формы в сериализации.

**Что запрещает**

- `∞` не является абитом;
- `[` и `]` не являются фигурными или круглыми скобками;
- `0` не вводится как прямая инверсия `1`.

**Открытые вопросы**

Связь `0` с сериализацией отсутствия и полная модель четверичной записи.

## Что не входит в рабочее ядро

Следующие элементы не считаются стабилизированными аксиомами:

- переменные как производный механизм;
- подстановка;
- операционное удаление в пучковой нотации;
- пустое `()` как самостоятельная форма;
- полная формализация позиционного чтения повторных `[]`;
- полная модель результата сравнения;
- строгая семантика `↛`;
- полная модель `:` для будущего апрувера.

Они перечислены в [Открытых вопросах новой аксиоматики МТС](../research/Открытые%20вопросы%20новой%20аксиоматики%20МТС.md).
