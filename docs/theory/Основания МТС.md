# Основания МТС

Статус: актуальное.

## Назначение

Документ фиксирует короткую рамку текущей МТС перед чтением системы аксиом и спецификаций нотации.

## Постулат

```text
всё есть связь
```

Это не означает, что все записи находятся на одном уровне. МТС различает связь, строковую запись формулы, формальную форму, форму одной связи, пучковую форму и асеть.

## Формальная нотация

Формальная нотация МТС — система смысловых различий.

```text
строковое ачисло
→ последовательность различий
→ формула
→ интерпретация формулы
→ связь / асеть связей
```

Каждая аксиома имеет формулу. Система формул аксиом решается одновременно. Корневая система формул является корневой библиотекой апрувера.

## Первичные скобочные нотации

```text
(...) — явная формальная форма / группировка формы
[...] — нотация ачисла; форма одной связи
{...} — пучковая нотация; форма пучка / асети связей
```

Скобки задают границы контейнера. Контейнер задаёт область чтения данной нотации.

## Акорень

Корневая формула:

```text
∞ : [] = [] ⟼ []
```

Рабочая фиксация пустой формы одной связи:

```text
[] = ∞
∞ = ∞ ⟼ ∞
```

`[]` здесь не является универсальной переменной. Это пустая форма одной связи в квадратной нотации.

## Группировка и последовательность

Круглые скобки явно фиксируют границу формальной формы:

```text
([]) = []
([][]) = [][]
([] ⟼ []) = [] ⟼ []
```

Две формы подряд читаются как связь:

```text
[][] : [] ⟼ []
[][] = [] ⟼ []
```

Три формы подряд собираются слева:

```text
[][][] : ([][]) ⟼ []
[][][] = ([] ⟼ []) ⟼ []
[][][] = [] ⟼ [] ⟼ []
```

Правая группировка требует явной формы и отличается от левой сборки:

```text
[]([][]) : [] ⟼ ([][])
[][][] != []([][])
[][][] != [] ⟼ ([] ⟼ [])
```

## Пучковая форма

Фигурные скобки описывают пучок / асеть связей:

```text
{} != []
{[]} != []
{[], []} = {[]}
{[], [][]} = {[][], []}
```

Пучковое раскрытие:

```text
[]{[], [][]} = {[] ⟼ [], [] ⟼ [][]}
{[], [][]}[] = {[] ⟼ [], [][] ⟼ []}
{[], [][]}{[], [][]} = {[] ⟼ [], [] ⟼ [][], [][] ⟼ [], [][] ⟼ [][]}
```

## Архитектурный принцип

Актуальная МТС должна быть короткой и строгой. Если конструкция требует внешнего универсального механизма, отдельной смысловой записи или нормативной внешней грамматики, она не входит в рабочее ядро до отдельной формализации.
