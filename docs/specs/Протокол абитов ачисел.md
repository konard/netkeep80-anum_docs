# Протокол абитов ачисел

Статус: актуальная рабочая спецификация для issue #61. Документ фиксирует основную протокольную проекцию абитов. Эта проекция пока не записывается напрямую в `tests/mtc_formulas.mtc` и не заменяет корневой fixture.

## Цель

Ачисловый протокол должен описывать связь так, чтобы сырой носитель ачисла мог быть загружен, передан, процитирован или использован для поиска без немедленного создания описываемой связи.

Главное правило этой спецификации: абиты нельзя мыслить как символы строки. Абиты читаются как минимальные стрелочные формы вокруг акорня, а строки вида `[]`, `][`, `[[` и `]]` читаются как связи между такими формами.

## Предельные формы

Рабочая гипотеза issue #61 вводит две предельные формы:

```text
α := ∞♀
β := ♂∞
```

Их протокольное чтение:

```text
α = ∞♀ = ∞ ⟼ α
β = ♂∞ = β ⟼ ∞
```

То есть:

```text
∞♀ — форма выхода из акорня к конечной самоформе
♂∞ — форма возврата от начальной самоформы к акорню
```

Это не строковое сокращение. Из `♂♀ = ∞` нельзя механически получать, что `∞♀` сводится к `♀` или что `♂∞` сводится к `♂`.

## Основная проекция абитов

Основной кандидат протокола:

```text
[ := α
] := β

0 := [] := α ⟼ β
1 := ][ := β ⟼ α
```

В развёрнутом виде:

```text
[ := ∞♀
] := ♂∞

0 := [] := ∞♀ ⟼ ♂∞
1 := ][ := ♂∞ ⟼ ∞♀
```

Это протокольная проекция, а не утверждение, что все контекстные смыслы `[]` и `][` исчерпаны значениями `0` и `1`.

## Четыре двухабитные формы

`[]` и `][` читаются не как строки, а как связи. Все четыре двухабитные формы существуют:

```text
[[ := α ⟼ α
[] := α ⟼ β
][ := β ⟼ α
]] := β ⟼ β
```

В развёрнутом виде:

```text
[[ := ∞♀ ⟼ ∞♀
[] := ∞♀ ⟼ ♂∞
][ := ♂∞ ⟼ ∞♀
]] := ♂∞ ⟼ ♂∞
```

Основная проекция:

```text
project_protocol([]) = 0
project_protocol(][) = 1
```

`[]` образует контейнерный обход:

```text
∞ → α → β → ∞
```

Поэтому `[]` является сильным кандидатом на несвязное описание, контейнер и абит `0`.

`][` образует прямую перемычку:

```text
β → α
```

Поэтому `][` является сильным кандидатом на связь, материализующий переход и абит `1`.

`][` не является ошибкой ведущей закрывающей скобки. `[[` и `]]` не являются ошибками. Они могут иметь собственный смысл в относительном, цитирующем или поисковом контексте, даже если в акорневом контексте позже будет введена нормализация.

## Критерии выбора

Вариант A является основным кандидатом:

```text
[ := α
] := β
[] := 0
][ := 1
```

Критерии:

1. Ачисло неявно начинается от `∞`, поэтому открывающий абит должен естественно исходить из акорня.
2. Обычная скобочная оболочка `[A]` должна работать как цитирование и контейнер, а не как немедленная материализация денотата `A`.
3. Поиск в апамяти должен получать описание связи, но не создавать искомую связь самим запросом.
4. Связь должна читаться как перемычка `β → α`, а не как контейнерный обход `∞ → α → β → ∞`.
5. Инверсия должна менять `0` и `1` на уровне формы обхода:

```text
¬([]) = ][
¬(][) = []
```

При этом `0` и `1` нельзя различать через `∞` и `¬∞`, потому что:

```text
∞ = ∞ ⟼ ∞
¬∞ = ∞ ⟼ ∞
¬∞ = ∞
```

Различение `0` и `1` находится в форме обхода:

```text
0 := α ⟼ β
1 := β ⟼ α
```

## Слои процедуры

Реализация должна различать операции:

```text
load(A)       — загрузить сырой носитель ачисла
decode(A)     — разобрать структуру носителя
project_K(A)  — применить контекст чтения K
realize(A)    — материализовать денотат в апамяти
find(A)       — проверить наличие денотата без создания
```

Для ачисла связи:

```text
A := ∞ab
raw(∞ab) = ((∞ ⟼ a) ⟼ b)
den(∞ab) = a ⟼ b
```

Ключевой инвариант:

```text
raw(∞ab) не содержит a ⟼ b
```

Следствия:

```text
load(∞ab) не создаёт a ⟼ b
realize(∞ab) создаёт или получает a ⟼ b
find(∞ab) проверяет наличие a ⟼ b, но не создаёт её
```

Загрузка строит или читает только последовательный носитель `((∞ ⟼ a) ⟼ b)`. Материализация уже работает с денотатом `a ⟼ b`.

## Цитирование

Скобочная оболочка повышает уровень описания:

```text
D(∞ab) = a ⟼ b
D([∞ab]) = ∞ab
D([[∞ab]]) = [∞ab]
```

Поэтому внешняя пара скобок должна быть нематериализующей оболочкой. Иначе запрос или цитата сразу создавали бы то, что должны только описывать.

## Контекстность

Одна и та же форма может иметь разные проекции:

```text
project(][, K_root) = 1
project(][, K_quote) = ][
project(][, K_relative) = переход между относительными контекстами
```

Поэтому десериализация должна зависеть от контекста `K`. В МТС нет онтологически запрещённых двухабитных форм; есть разные контекстные проекции существующих стрелочных форм.

## Связь с корневым fixture

Текущий корневой fixture сохраняется без прямой записи новой проекции. Рабочее чтение протокола:

```text
[ := ∞♀
] := ♂∞
[] := 0
][ := 1
```

пока не записывается напрямую в `tests/mtc_formulas.mtc`. В корневой библиотеке остаются нормативные записи:

```text
([) : (♀∞)
(]) : (∞♂)
[1] : (⟼)
[0] : (↛)
```

Этот документ задаёт слой протокольного чтения и критерии будущей реализации `load`, `decode`, `project_K`, `realize` и `find`.
