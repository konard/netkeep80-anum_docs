# Формальная нотация МТС

Статус: рабочее.

Эта спецификация описывает смыслы связей и шаблоны поиска смыслов. Она не является записью ачисел и не должна смешиваться с сериализацией.

## Назначение

Формальная запись отвечает на вопрос:

```text
какой смысл связи ищется и по какой форме он распознаётся?
```

Она не описывает напрямую байтовую структуру, абитовое ачисло или конкретную асеть.

## Базовые правила

```text
{} — шаблонный поиск без фильтра
```

`{}` обозначает связь-кандидат текущего шаблонного контекста. Она становится определённой только через форму, в которой участвует.

Запрещённые чтения:

```text
{} ≠ пустое множество
{} ≠ пустой результат поиска
{} ≠ несвязь
{} ≠ 0
```

Внутри одного исполнения шаблона все одинаковые вхождения `{}` относятся к одной и той же связи-кандидату.

Для акорня:

```text
∞ : {} = {} ⟼ {}
```

это означает поиск одного `X`, для которого:

```text
X = X ⟼ X
```

а не независимых `A`, `B`, `C`, для которых:

```text
A = B ⟼ C
```

Исполнение шаблона — это нахождение связи-кандидата, удовлетворяющей ограничениям формы, и связывание найденного смысла с вводимым знаком.

## `{}` и `{s}`

`{}` и `{s}` — разные конструкции одного внешнего синтаксиса:

```text
{}  — пустой фильтр поиска / связь-кандидат шаблона
{s} — смысловая ссылка на знак s
```

{} не является частным случаем `{s}`.
{s} не является поиском без фильтра.

Примеры смысловых ссылок:

```text
{[} : ∞♀
{]} : ♂∞
{⟼} : {[} ⟼ {]}
```

## Реестр символов

Каждый символ формальной нотации должен быть либо введён аксиомой, либо явно помечен как служебная запись.

| Элемент | Актуальный статус | Слой | Допустимое использование | Запрещённое использование | Нужна ли аксиома |
|---------|-------------------|------|--------------------------|---------------------------|------------------|
| `∞` | знак смысла полного самозамыкания | смысл связи | аксиома `∞ : {} = {} ⟼ {}` | абит или текстовая константа сериализации | да, А1 |
| `{}` | шаблонная конструкция | шаблон поиска | один кандидат текущего исполнения | пустое множество, пустой результат, несвязь, `0` | служебная запись; точный статус скобок открыт |
| `{s}` | смысловая ссылка | формальная нотация | ссылка на смысл знака `s` | поиск без фильтра или контейнер | служебная запись; смысл конкретного `s` задаётся аксиомой |
| `{` | служебный знак записи | формальная нотация | начало `{}` или `{s}` | объектный символ МТС без статуса | открыт вопрос |
| `}` | служебный знак записи | формальная нотация | конец `{}` или `{s}` | объектный символ МТС без статуса | открыт вопрос |
| `:` | рабочий механизм введения | формальная нотация | `s : F`, ввод знака для найденного смысла | простое присваивание имени объекту | нужна будущая аксиома |
| `=` | рабочее отношение неразличимости | формальная нотация | структурная неразличимость после исполнения шаблона | текстовое равенство или результат поиска | нужна будущая аксиома |
| `⟼` | бинарный конструктор связи | формальная нотация / смысл связи | `A ⟼ B`, связь формы `A` с формой `B` | нульарное имя без `{⟼}` | да, А6 для смысла конструктора |
| `♂` | унарный префиксный вид формы | формальная нотация | `♂A`, самозамкнутое начало | самостоятельная связь без операнда | да, А2 |
| `♀` | унарный постфиксный вид формы | формальная нотация | `A♀`, самозамкнутый конец | самостоятельная связь без операнда | да, А3 |
| `¬` | нестабилизированный вид формы | формальная нотация | только как открытый вопрос инверсии | текущая аксиома ядра | нужна будущая аксиома или отказ |
| `↛` | нестабилизированный знак несвязи | смысл связи | только как открытый вопрос | замена `{}` или `0` | нужна будущая аксиома |
| `[` | абит начала | ачисла / сериализация | символ четверичной сериализации; смысл через `{[}` | формальная группировка, экранирование | смысловая аксиома А4 |
| `]` | абит конца | ачисла / сериализация | символ четверичной сериализации; смысл через `{]}` | формальная группировка, экранирование | смысловая аксиома А5 |
| `1` | абит наличия связи | ачисла / сериализация | практическая четверичная запись | стабилизированный смысловой знак ядра | открыт вопрос для смысловой аксиомы |
| `0` | абит отсутствия связи | ачисла / сериализация | практическая четверичная запись | пустой результат поиска, `{}` или `↛` | открыт вопрос для смысловой аксиомы |
| `(` | служебная группировка | формальная запись | явная группировка формулы | абит ачисла | аксиома не нужна, это запись |
| `)` | служебная группировка | формальная запись | явная группировка формулы | абит ачисла | аксиома не нужна, это запись |
| `,` | метаязыковый разделитель | метаязык | списки в пояснениях | оператор объектной МТС | аксиома не нужна |

## Рабочий синтаксис

Это ограничивающий набросок, а не финальная BNF-грамматика:

```text
definition  ::= sign ":" form
form        ::= candidate
              | reference
              | form "⟼" form
              | "♂" form
              | form "♀"
              | "¬" form
              | form "=" form
              | "(" form ")"
candidate   ::= "{}"
reference   ::= "{" sign "}"
sign        ::= "∞" | "⟼" | "↛" | "[" | "]" | "1" | "0" | name
```

`name` — метаязыковое имя вводимого знака. Оно не делает латинские переменные внутренними символами МТС.

## Приоритеты

Временные приоритеты до стабилизации парсера:

| Приоритет | Операция |
|-----------|----------|
| 1 | `{s}`, `{}` |
| 2 | `♂A`, `A♀`, `¬A` |
| 3 | `A ⟼ B` |
| 4 | `A = B` |
| 5 | `s : F` |

Если есть риск неоднозначности, используются круглые скобки.

## Что не входит в рабочую нотацию

В рабочую формальную нотацию не входят:

- грамматики, где `x`, `a`, `b` объявлены термами объектного языка;
- трактовка `{}` как пустого контейнера;
- использование `[` и `]` как формульных скобок;
- смешение формальной записи, строкового ачисла, четверичного ачисла и асети.
