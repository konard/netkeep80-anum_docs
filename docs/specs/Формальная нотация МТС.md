# Формальная нотация МТС

Статус: рабочее.

## Назначение

Формальная нотация МТС — система смысловых различий.

```text
формальная нотация МТС = система смысловых различий
```

Строка формальной нотации МТС есть строковое ачисло, содержащее запись формулы. Формула есть последовательность различий, прочитанная как шаблон формы связи. Интерпретация формулы даёт связь или асеть связей.

```text
строковое ачисло
→ последовательность различий
→ формула
→ интерпретация формулы
→ связь / асеть связей
```

Формальная нотация не является внешней грамматикой, которая стоит над МТС. Она является внутренней корневой системой различий, через которую описываются формы связей и способы чтения других нотаций.

## Базовые положения

```text
всё есть связь
формальная нотация МТС работает с формами связей
все описываемые нотации являются шаблонами форм связей
```

Каждая аксиома имеет формулу формальной нотации МТС. Система формул аксиом решается одновременно. Корневая система формул является корневой библиотекой апрувера.

Иначе: корневая библиотека апрувера — это одновременно решаемая система формул аксиом.

Документация поясняет формулы, но не заменяет их. Если у аксиомы нет формулы, она не входит в корневую библиотеку как аксиома.

## Первичные скобочные нотации

```text
(...) — явная формальная форма / группировка формы
[...] — нотация ачисла; форма одной связи
{...} — пучковая нотация; форма пучка / асети связей
```

Скобки являются границами контейнера нотации:

```text
скобки = границы контейнера
контейнер = область чтения данной нотации
нотация = способ интерпретации различий внутри контейнера
```

Контекст чтения задаётся внешним окружением контейнера. Он не заменяет сам контейнер и не вводит новую пару скобок.

## Пустые формы

Пустая форма конкретной нотации не является универсальной переменной.

```text
[] — пустая форма одной связи
{} — пустая форма пучка связей
```

Статус пустой круглой формы остаётся открытым вопросом. В рабочем ядре круглые скобки применяются к уже имеющейся форме:

```text
([]) = []
([][]) = [][]
([] ⟼ []) = [] ⟼ []
```

## Двоеточие

Форма:

```text
A : F
```

читается так:

```text
A вводится как различие, смысл которого распознаётся по формуле F
```

: не является процедурным присваиванием.

```text
: не является процедурным присваиванием
: не означает выполнить правую часть и записать результат слева
```

Если правая формула требует явной границы, используются круглые скобки:

```text
A : (F)
```

Когда формальная нотация находится внутри формальной нотации и приоритет однозначен, круглые скобки могут быть опущены:

```text
∞ : [] = [] ⟼ []
```

читается как:

```text
∞ : ([] = [] ⟼ [])
```

## Корневая система формул

Минимальная рабочая фиксация пустой формы одной связи:

```text
∞ : [] = [] ⟼ []
[] = ∞
∞ = ∞ ⟼ ∞
```

`[]` здесь не является переменной. Это пустая форма одной связи в квадратной нотации. Акорень вводится через шаблон полного самозамыкания пустой формы одной связи.

`[] = ∞` означает, что минимальная ачисловая форма `[]` является записью акорня. ∞ не является абитом. Абитами являются `[`, `]`, `1`, `0`.

Формула после `:` задаёт локальный шаблон распознавания. Внутри аксиомы `∞` повторные `[]` читаются как один образец пустой формы одной связи. Это не означает глобального схлопывания всех форм `[][]` в `[]`: последовательность `[][]` читается позиционно как две формы связи.

## Круглая группировка

Круглая нотация явно выделяет формальную форму как единое различие:

```text
([]) = []
([][]) = [][]
([] ⟼ []) = [] ⟼ []
```

Круглые скобки опциональны там, где приоритет однозначен, но обязательны там, где нужно различить группировку:

```text
[][][] != []([][])
[][][] != [] ⟼ ([] ⟼ [])
```

## Последовательность

Две формы подряд читаются как связь:

```text
[][] : [] ⟼ []
[][] = [] ⟼ []
```

Три формы подряд собираются слева:

```text
[][][] : ([][]) ⟼ []
[][][] = ([] ⟼ []) ⟼ []
[][][] = [] ⟼ [] ⟼ []
```

Явная правая группировка отличается от левой сборки:

```text
[]([][]) : [] ⟼ ([][])
[][][] != []([][])
[][][] != [] ⟼ ([] ⟼ [])
```

## Самозамкнутые формы

```text
♂[] : ♂[] = ♂[] ⟼ []
♂∞ = ♂∞ ⟼ ∞

[]♀ : []♀ = [] ⟼ []♀
∞♀ = ∞ ⟼ ∞♀
```

## Связь и смысл связи

Нужно различать смысл связи и конкретную связь:

```text
(⟼) : [] ⟼ []
[⟼] : ∞♀ ⟼ ♂∞
```

`(⟼)` — смысл связи как формы связи одной связи с другой связью.

`[⟼]` — конкретная связь как связь начала акорня с концом акорня.

Начало и конец акорня возвращаются в корневую систему через конкретную связь:

```text
∞♀ : [⟼]♀
♂∞ : ♂[⟼]
```

Итоговое различение уровней:

```text
[]      — пустая форма одной связи / ачисловая запись ∞
∞       — конкретный акорень / смысл полного самозамыкания
[][]    — последовательность двух форм связи
[⟼]     — конкретная связь
(⟼)     — смысл связи
```

## Инверсия

Инверсия формы связи задаётся как связь конца формы с её началом:

```text
¬[] : ♂[] ⟼ []♀
```

Для конкретной связи фиксируются две согласованные записи:

```text
¬[⟼] : ♂[⟼] ⟼ [⟼]♀
¬[⟼] : ♂∞ ⟼ ∞♀
```

Итоговое чтение:

```text
[⟼]  : ∞♀ ⟼ ♂∞
¬[⟼] : ♂∞ ⟼ ∞♀
```

`¬` применяется к смыслу или к результату применения смысла, но не должен неявно применяться к конкретной связи знака.

## Равенство и результат сравнения

Смысл равенства вводится через совпадение начал и концов сравниваемых форм связи:

```text
(=) : {[]♀ = []♀, ♂[] = ♂[]}
```

Метаязыковое чтение:

```text
A = B
⇔
A♀ = B♀
и
♂A = ♂B
```

В этой формуле повторные `[]` читаются позиционно: левая форма и правая форма равны, если равны их начала и равны их концы. Это остаётся задачей будущего апрувера как строгая модель позиционного чтения, но сама формула входит в рабочий корень.

## Неравенство как инверсия смысла равенства

Неравенство вводится как инверсия смысла равенства:

```text
(!=) : ¬(=)
[] != [] : ¬([] = [])
```

Нужно различать:

```text
(=)   — смысл равенства
[=]   — конкретная связь знака равенства, если она будет введена
[]=[] — результат конкретного сравнения
```

`¬[=] не означает !=`. Инверсия конкретной связи знака равенства не является смыслом неравенства.

## Абиты квадратной нотации

Квадратная нотация вводит абиты `[`, `]`, `1`, `0`:

```text
[ : ∞♀
] : ♂∞
1 : [⟼]
↛ : ¬[⟼]
0 : [↛]
```

`[` — абит начала. `]` — абит конца. `1` — абит конкретной связи. `↛` вводит несвязь как инверсию конкретной связи. `0` — абит несвязи / отсутствия связевой формы в сериализации.

`0` не отождествляется напрямую с инверсией связи: промежуточная формула `↛ : ¬[⟼]` сохраняет различие между инверсией конкретной связи и абитом отсутствия.

## Фигурная нотация

Фигурная нотация описывает пучок или асеть связей:

```text
{} != []
{[]} != []
{[], []} = {[]}
{[], [][]} = {[][], []}
```

Пучковое раскрытие:

```text
[]{[], [][]} = {[] ⟼ [], [] ⟼ [][]}
{[], [][]}[] = {[] ⟼ [], [][] ⟼ []}
{[], [][]}{[], [][]} = {[] ⟼ [], [] ⟼ [][], [][] ⟼ [], [][] ⟼ [][]}
```

Подробное чтение находится в [Пучковой нотации МТС](Пучковая%20нотация%20МТС.md).

## Реестр различий

Каждый элемент активной формальной записи должен быть либо введён формулой, либо явно помечен как служебная запись или открытый вопрос.

| Элемент | Актуальный статус | Слой | Допустимое использование | Открытый вопрос |
|---------|-------------------|------|--------------------------|-----------------|
| `∞` | знак полного самозамыкания | форма связи | результат фиксации `[] = ∞` | нет |
| `[]` | пустая форма одной связи | квадратная нотация | корневая форма одной связи | позиционное чтение повторов |
| `{}` | пустой пучок связей | пучковая нотация | пустой пучок / асеть связей | операции над пустым пучком |
| `()` | явная формальная группировка | формальная нотация | граница уже имеющейся формы | статус пустой формы |
| `:` | введение различия через формулу | формальная нотация | `A : F` | отдельная аксиоматизация |
| `=` | результат сравнения форм | формальная нотация | фиксация совпадения форм | полная модель результата |
| `!=` | результат инверсии сравнения | формальная нотация | фиксация нетождественности форм | тип результата сравнения |
| `⟼` | знак связи внутри формул | форма связи | `A ⟼ B` | полная собственная аксиома знака |
| `(⟼)` | смысл связи | формальная нотация | связь одной формы с другой | нет |
| `[⟼]` | конкретная связь | квадратная нотация | связь начала акорня с концом акорня | нет |
| `¬` | инверсия смысла или результата | формальная нотация | `¬[]`, `¬(=)`, `¬([] = [])` | строгие границы применения |
| `↛` | несвязь | формальная нотация / квадратная нотация | промежуточный смысл для абита `0` | строгая семантика |
| `♂` | префиксный вид формы | форма связи | `♂A` | связь с началом связи |
| `♀` | постфиксный вид формы | форма связи | `A♀` | связь с концом связи |
| `[` | абит начала | квадратная нотация | `[ : ∞♀` | нет |
| `]` | абит конца | квадратная нотация | `] : ♂∞` | нет |
| `1`, `0` | абиты конкретной связи и несвязи | четверичная запись | `1 : [⟼]`, `0 : [↛]` | связь `0` с сериализацией отсутствия |
| `,` | разделитель перечисления | пучковая нотация | элементы внутри `{...}` | объектный статус не вводится |

## Что не входит в рабочее ядро

В рабочее ядро не входят:

- универсальный внешний placeholder;
- новая внешняя пара смысловых скобок;
- смысловая ссылка на знак как принятая формула ядра;
- нормативная внешняя грамматика;
- операционное удаление в пучковой нотации;
- переменные как первичный механизм;
- подстановка;
- пустое `()` как самостоятельный результат.

Эти темы вынесены в [Открытые вопросы новой аксиоматики МТС](../research/Открытые%20вопросы%20новой%20аксиоматики%20МТС.md).

Канонический набор формул текущей нотации находится в `tests/mtc_formulas.mtc` и проверяется регрессионными тестами документации. На текущем этапе fixture фиксирует корневую библиотеку для будущего апрувера: список формул, допустимые различия и отсутствие вынесенных за пределы ядра механизмов.
