# Пучковая нотация МТС

Статус: рабочее.

## Назначение

Пучковая нотация использует фигурные скобки `{...}` как контейнер пучка / асети связей.

```text
{...} — пучковая нотация; пучок / асеть связей
```

Пучок — различённый набор связей в данном контексте чтения. Пучок и его элемент принадлежат разным слоям различения: пучок описывает набор связей, а элемент — отдельную форму одной связи.

## Базовые формулы

В корневом ядре пучковая нотация задаётся через базовые формы `[]` и `[][]`:

```text
{} != []
{[]} != []
{[], []} = {[]}
{[], [][]} = {[][], []}
```

Смысл:

- `{}` — пустой пучок связей;
- `{[]}` — одноэлементный пучок из пустой формы одной связи;
- пучок и его элемент принадлежат разным слоям различения;
- порядок элементов не важен;
- пучок удерживает каждую форму один раз (экстенсиональность).

## Экстенсиональное чтение

Рабочее чтение пучка экстенсионально:

```text
{[], []} = {[]}
{[], [][]} = {[][], []}
```

Порядок элементов не важен, а кратность не сохраняется. Мультпучковая версия с сохранением кратности остаётся открытым вопросом.

## Правое пучковое раскрытие

Форма:

```text
[]{[], [][]}
```

читается как пучок исходящих связей от формы `[]` к каждому элементу правого пучка:

```text
[]{[], [][]} = {[] ⟼ [], [] ⟼ [][]}
```

## Левое пучковое раскрытие

Форма:

```text
{[], [][]}[]
```

читается как пучок входящих связей в форму `[]` от каждого элемента левого пучка:

```text
{[], [][]}[] = {[] ⟼ [], [][] ⟼ []}
```

## Двустороннее пучковое раскрытие

Форма:

```text
{[], [][]}{[], [][]}
```

читается как пучок всех связей от каждого элемента левого пучка к каждому элементу правого пучка:

```text
{[], [][]}{[], [][]} = {[] ⟼ [], [] ⟼ [][], [][] ⟼ [], [][] ⟼ [][]}
```

## Пустое пучковое раскрытие

Пустой правый пучок:

```text
[]{} = {}
```

Пустой левый пучок:

```text
{}[] = {}
```

Эти формулы являются только частным случаем раскрытия по явно пустому пучку. Они фиксируют, что раскрытие по пустому пучку даёт пустой пучок связей.

`[]{} = {}` и `{}[] = {}` не являются удалением связей. Они не выражают "все исходящие связи" и "все входящие связи", не задают операционное изменение асети и не должны читаться как команда удаления.

Операционное чтение `[]{}` и `{}[]` ведётся в слое развития, потому что для него нужен отдельный механизм обобщения "все исходящие связи" / "все входящие связи".

## Роль в корневой системе

Пучковая нотация входит в корневой fixture как способ описания пучка / асети связей:

```text
{} != []
{[]} != []
{[], []} = {[]}
{[], [][]} = {[][], []}

[]{[], [][]} = {[] ⟼ [], [] ⟼ [][]}
{[], [][]}[] = {[] ⟼ [], [][] ⟼ []}
{[], [][]}{[], [][]} = {[] ⟼ [], [] ⟼ [][], [][] ⟼ [], [][] ⟼ [][]}
[]{} = {}
{}[] = {}
```

Эти строки фиксируют:

1. пустой пучок отличается от пустой формы одной связи;
2. одноэлементный пучок отличается от своего элемента;
3. пучок берётся экстенсиональным;
4. правое, левое и двустороннее раскрытие строят пучок явных связей;
5. раскрытие по явно пустому пучку даёт пустой пучок в описательном чтении и не является удалением связей.

## Слой развития

Операционное изменение асети ведётся в слое развития: для него нужен отдельный механизм обобщения или переменных, который выразит "все исходящие связи" или "все входящие связи". Пока корневая система описывает пучок через явные формулы fixture.

В слой развития также вынесены:

- переменные как первичные элементы;
- подстановка;
- мультпучки с сохранением кратности;
- восстановление пучковой записи из четверичного ачисла;
- связь пучковой нотации с остенсивной асетью за пределами формул fixture.
