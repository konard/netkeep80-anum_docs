# Пучковая нотация МТС

Статус: рабочее.

Эта спецификация вводит отдельную **пучковую нотацию** на фигурных скобках `{}`. Фигурные скобки описывают не шаблонный поиск и не смысловую ссылку, а **пучок связей** — различённый набор связей, заданный перечислением или раскрываемый через левое и правое применение к связи.

## Назначение

Формальная нотация МТС понимается как метанотация: она описывает другие нотации, их контексты чтения, роли знаков и аксиомы перехода между ними.

```text
связи
→ четверичные ачисла
→ строковые ачисла
→ формальная нотация МТС
→ метаописание нотаций, контекстов и смыслов
```

В этой рамке фигурные скобки занимают отдельную роль:

```text
{}       — пучок связей / пучковая нотация
□        — шаблонный слот / кандидат шаблонного поиска
⟦s⟧N     — смысл знака s в нотации N
()       — группировка формы
[]       — абиты четверичной нотации ачисел
```

Это устраняет прежнюю перегрузку фигурных скобок, где `{}` означало шаблонный поиск, а `{s}` — смысловую ссылку. После введения пучковой нотации:

```text
{}    было: шаблонный поиск без фильтра
{}    стало: пустой пучок / пучковая нотация

□     новое: шаблонный слот / кандидат поиска

{s}   было: смысловая ссылка на знак s
⟦s⟧N  стало: смысл знака s в нотации N
```

где `Q` — четверичная нотация ачисел, `F` — формальная нотация МТС.

## Что такое пучок

```text
{x, y}
```

означает пучок, содержащий связи `x` и `y`.

Пучок — это не обязательно классическое множество ZF. В рабочей рамке его лучше понимать как:

```text
пучок = различённый набор связей в данном контексте чтения
```

Рабочее экстенсиональное чтение:

```text
{x, y} = {y, x}
{x, x} = {x}
```

То есть порядок элементов не важен, а повтор элемента не создаёт новый элемент пучка.

Одноэлементный пучок и сам элемент не отождествляются:

```text
{x} ≠ x
```

Здесь `x`, `y`, `z`, `a`, `b` — метаязыковые имена элементов пучка, а не внутренние знаки МТС.

## Правое пучковое раскрытие: исходящие связи

Форма:

```text
a{x, y}
```

означает пучок исходящих связей из `a` к каждому элементу правого пучка.

```text
a{x, y} = {a ⟼ x, a ⟼ y}
```

Общее правило:

```text
a{b₁, b₂, ..., bₙ}
=
{a ⟼ b₁, a ⟼ b₂, ..., a ⟼ bₙ}
```

Примеры:

```text
a{x}     = {a ⟼ x}
a{x, y}  = {a ⟼ x, a ⟼ y}
a{x,y,z} = {a ⟼ x, a ⟼ y, a ⟼ z}
```

## Левое пучковое раскрытие: входящие связи

Форма:

```text
{x, y}a
```

означает пучок входящих связей в `a` от каждого элемента левого пучка.

```text
{x, y}a = {x ⟼ a, y ⟼ a}
```

Общее правило:

```text
{b₁, b₂, ..., bₙ}a
=
{b₁ ⟼ a, b₂ ⟼ a, ..., bₙ ⟼ a}
```

Примеры:

```text
{x}a     = {x ⟼ a}
{x, y}a  = {x ⟼ a, y ⟼ a}
{x,y,z}a = {x ⟼ a, y ⟼ a, z ⟼ a}
```

## Двустороннее пучковое раскрытие

Форма:

```text
{x, y}{a, b}
```

означает пучок всех связей от каждого элемента левого пучка к каждому элементу правого пучка.

```text
{x, y}{a, b}
=
{x ⟼ a, x ⟼ b, y ⟼ a, y ⟼ b}
```

Общее правило:

```text
{x₁, ..., xₙ}{y₁, ..., yₘ}
=
{xᵢ ⟼ yⱼ | i = 1..n, j = 1..m}
```

Пример:

```text
{a, b}{x, y}
=
{a ⟼ x, a ⟼ y, b ⟼ x, b ⟼ y}
```

## Пустой пучок

```text
{}
```

означает пустой пучок связей.

Важно различать пустой пучок и другие конструкции:

```text
{} ≠ шаблонный кандидат
{} ≠ произвольная связь
{} ≠ смысловая ссылка
```

Для произвольного кандидата шаблонного поиска используется отдельный знак `□`.

### Пустой правый пучок: удаление исходящих связей

Форма `a{}` имеет два связанных чтения.

Описательное чтение:

```text
a{} = {}
```

То есть исходящий пучок `a` пуст.

Операционное чтение:

```text
a{} : a -/> {}
```

То есть привести исходящий пучок `a` к пустому состоянию — удалить все исходящие связи из `a`:

```text
delete {a ⟼ □}
```

где `□` — произвольный конец исходящей связи.

### Пустой левый пучок: удаление входящих связей

Форма `{}a` имеет два связанных чтения.

Описательное чтение:

```text
{}a = {}
```

То есть входящий пучок `a` пуст.

Операционное чтение:

```text
{}a : {} -/> a
```

То есть привести входящий пучок `a` к пустому состоянию — удалить все входящие связи в `a`:

```text
delete {□ ⟼ a}
```

Пустой пучок стоит слева от `a`, поэтому удаляются именно **входящие** связи.

## Частичное удаление связей

### Удаление правого пучка

```text
a -/> {x, y}
:
delete {a ⟼ x, a ⟼ y}
```

### Удаление левого пучка

```text
{x, y} -/> a
:
delete {x ⟼ a, y ⟼ a}
```

## Система аксиом пучковой нотации

### B0. Пустой пучок

```text
{} : пустой пучок связей
```

### B1. Одноэлементный пучок

```text
{x} : пучок, содержащий x
```

Одноэлементный пучок и сам элемент не отождествляются: `{x} ≠ x`.

### B2. Экстенсиональность пучка

```text
{x, y} = {y, x}
{x, x} = {x}
```

Пучок берётся экстенсиональным: порядок не важен, кратность не сохраняется. Мультпучковая нотация с сохранением кратности остаётся открытым вопросом.

### B3. Правое пучковое раскрытие

```text
a{x, y} : {a ⟼ x, a ⟼ y}
a{x, y} = {a ⟼ x, a ⟼ y}
```

Общее правило:

```text
a{b₁, ..., bₙ}
=
{a ⟼ b₁, ..., a ⟼ bₙ}
```

### B4. Левое пучковое раскрытие

```text
{x, y}a : {x ⟼ a, y ⟼ a}
{x, y}a = {x ⟼ a, y ⟼ a}
```

Общее правило:

```text
{b₁, ..., bₙ}a
=
{b₁ ⟼ a, ..., bₙ ⟼ a}
```

### B5. Двустороннее пучковое раскрытие

```text
{x, y}{a, b}
=
{x ⟼ a, x ⟼ b, y ⟼ a, y ⟼ b}
```

Общее правило:

```text
{x₁, ..., xₙ}{y₁, ..., yₘ}
=
{xᵢ ⟼ yⱼ | i = 1..n, j = 1..m}
```

### B6. Пустой правый пучок

```text
a{} : a -/> {}
a{} = {}
```

Операционное чтение:

```text
delete {a ⟼ □}
```

### B7. Пустой левый пучок

```text
{}a : {} -/> a
{}a = {}
```

Операционное чтение:

```text
delete {□ ⟼ a}
```

### B8. Частичное удаление исходящих связей

```text
a -/> {x, y}
:
delete {a ⟼ x, a ⟼ y}
```

### B9. Частичное удаление входящих связей

```text
{x, y} -/> a
:
delete {x ⟼ a, y ⟼ a}
```

## Нормальная форма и операционный смысл

Нормальная форма `NF(...)` разворачивает пучковое выражение в пучок явных связей:

```text
NF(a{x, y})      = {a ⟼ x, a ⟼ y}
NF({x, y}a)      = {x ⟼ a, y ⟼ a}
NF({x, y}{a, b}) = {x ⟼ a, x ⟼ b, y ⟼ a, y ⟼ b}
NF(a{})          = {}
NF({}a)          = {}
```

Операционный смысл `OP(...)` отделяется от нормальной формы и описывает удаление связей:

```text
NF(a{})  = {}
OP(a{})  = delete {a ⟼ □}

NF({}a)  = {}
OP({}a)  = delete {□ ⟼ a}
```

Описательное чтение пучка (`NF`) и операционное чтение удаления связей (`OP`) нельзя смешивать: первое описывает состояние пучка, второе задаёт действие над асетью.

## Отделение от шаблонного поиска и смысловой ссылки

Пучковая нотация не смешивается с другими ролями фигурных скобок прошлой рамки:

```text
{}    — пустой пучок, а не шаблонный кандидат
□     — шаблонный слот / кандидат шаблонного поиска
⟦s⟧N  — смысл знака s в нотации N
```

Старая формула акорня

```text
∞ : {} = {} ⟼ {}
```

в новой рамке записывается через шаблонный слот:

```text
∞ : □ = □ ⟼ □
```

Старые смысловые ссылки

```text
{[}
{]}
{⟼}
```

записываются как явное чтение знака в контексте нотации:

```text
⟦[⟧Q : ∞♀
⟦]⟧Q : ♂∞
⟦⟼⟧F : ⟦[⟧Q ⟼ ⟦]⟧Q
```

## Открытые вопросы

1. Является ли пучок экстенсиональным `{x, x} = {x}` или нужна мультпучковая версия с сохранением кратности?
2. Должна ли пучковая нотация быть частью формальной нотации МТС или отдельной нотацией, описываемой формальной метанотацией?
3. Как пучковая нотация восстанавливается в четверичных ачислах?
4. Как пучковая нотация связана с асетью как остенсивной структурой?
5. Является ли `a{}` только описанием пустого исходящего пучка или также командой удаления, и как фиксировать это различие через `NF` и `OP`?
