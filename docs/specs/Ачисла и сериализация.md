# Ачисла и сериализация

Статус: актуальное, нормативное для квадратной записи.

## Назначение

ачисло — последовательность абитов, интерпретируемая в ассоциативном контексте.

Квадратная нотация используется для формы одной связи и для квадратных форм абитов.

## Скобочные формы

```text
[] — минимальная завершённая форма одной связи
() — минимальная формальная форма смысла
{} — пустой пучок связей
```

Эти формы различаются и не заменяют друг друга.

## Квадратные абиты

[ и ] — квадратные абиты полюсов формы.

```text
([) : (♀∞)
(]) : (∞♂)
```

В круглых формах `([)` и `(])` квадратные знаки читаются как буквальные абиты.

## Абиты связи и несвязи

```text
[1] — квадратная форма абита связи
[0] — квадратная форма абита несвязи
```

```text
[1] : (⟼)
[0] : (↛)
```

0 не означает отсутствие связи в натуре. 0 означает абит связи, несущей смысл несвязи.

```text
0 — абит связи, несущей смысл несвязи
↛ — смысл несвязи
```

Несвязь не существует в натуре. Смысл несвязи выражается связью.

## Связь с акорнем

```text
∞ : [] = [] ⟼ []
[] = ∞
∞ = ∞ ⟼ ∞
```

Акорень несёт смысл смысла. `[]` является минимальной завершённой формой одной связи и записью акорня в квадратной нотации.

## Инверсия

Инверсия связи меняет направление натуральной связи. Инверсия смысла меняет смысл на обратный. Обратное направление связи не является отсутствием связи. Абит 0 не является отсутствием связи в натуре.

## Протокол абитов как стрелочных форм

Рабочая проекция абитов, скобок, связи и несвязи описана в спецификации [Протокол абитов ачисел](<Протокол абитов ачисел.md>).

Эта проекция фиксирует абиты не как символы строки, а как минимальные стрелочные формы вокруг акорня. Она задаёт различение `load`, `decode`, `project_K`, `realize` и `find`, чтобы загрузка или поиск ачисла не создавали искомую связь раньше материализующего контекста.

Эта проекция пока не записывается напрямую в `tests/mtc_formulas.mtc`: рабочее чтение `[ := ∞♀`, `] := ♂∞`, `[] := 0`, `][ := 1` остаётся протокольным слоем, а текущие квадратные абитовые формы `[1] : (⟼)` и `[0] : (↛)` остаются нормативной поверхностью корневой библиотеки.

## Формат файлов `*.anum`

Файл `*.anum` имеет один из двух режимов:

```text
# anum-format: quaternary
# anum-format: string
```

Если заголовка нет, файл читается как `quaternary`.

Строгий четверичный режим принимает только значащие абиты:

```text
[ ] 1 0
```

Пробелы, переводы строк и комментарии `# ...` до конца строки игнорируются. Любой другой символ в `quaternary` является ошибкой. Обычная скобочная балансировка к этому слою не применяется: `][`, `[[`, `]]` и `[]` являются допустимыми последовательностями абитов.

Строковый режим является отдельным человекочитаемым слоем. Имена, строки и словарные ярлыки допустимы только при явном заголовке:

```text
# anum-format: string
window(position)(x)(10(int))
```

Один parser не должен молча смешивать произвольные имена со строгой четверичной записью.

## Практический прототип

Текущий код разделяет слои:

```text
core/anum_parser.py      parser `*.anum`
core/anum_projector.py   проекция двухабитных форм
core/anum_memory.py      минимальная symbolic-модель load/find/realize
converters/anum_cli.py   CLI для parse/project/normalize/realize
```

Проекция двух квадратных абитов:

```text
[[ := α ⟼ α
[] := α ⟼ β -> 0
][ := β ⟼ α -> 1
]] := β ⟼ β
```

`[[` и `]]` распознаются как существующие формы без ошибки, но на этом шаге не получают основного значения `0` или `1`.

Минимальная symbolic-модель фиксирует инвариант:

```text
load(A)    не создаёт den(A)
find(A)    проверяет den(A), но не создаёт den(A)
realize(A) создаёт den(A), если den(A) является связью
```

Для символического ачисла `A = SymbolicAnum("a", "b")`:

```text
den(A) = a ⟼ b
den([A]) = A
den([[A]]) = [A]
```

Эта модель является тестовой проверкой протокольного инварианта, а не полноценной апамятью.

## CLI

Минимальные команды:

```bash
python -m converters.anum_cli parse examples/anum/two_abit_forms.anum
python -m converters.anum_cli project examples/anum/two_abit_forms.anum
python -m converters.anum_cli normalize examples/anum/text_payload_hello.anum
python -m converters.anum_cli realize examples/anum/string_symbolic_link.anum
```

## Практические конвертеры

Конвертеры `converters/text_to_anum.py` и `converters/anum_to_text.py` сохраняют обратимость практической сериализации UTF-8 текста в последовательность `1` и `0`.

```text
"hello" -> [01101000][01100101][01101100][01101100][01101111]
```

Этот слой является UTF-8 payload codec. Он не является десериализатором связей и не заменяет `load`, `decode`, `project_K`, `find` или `realize`. Практическая сериализация текста не меняет онтологическое чтение: `0` остаётся абитом связи, несущей смысл несвязи.
